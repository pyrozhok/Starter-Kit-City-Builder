## Lessons → skill changes

- The false finding #6 came from a test-framework assumption ("a failed assert stops the test") that was never checked. This is the same pattern as 002 and 003: a check counts only when it covers what the finding claims. Here the claim was about GUT's runtime, and reading the test code couldn't settle it. Step 5 of `review-pr` now says GUT asserts don't abort, and not to suggest moving cleanup on that ground (`5297b37`).
- Wins:
  - Picking the base from `fork/main` instead of the stale local `main` kept the diff at 66 files.
  - The Blocking finding was reproduced (probe) rather than inferred, and its fix landed with a test that is red on the old code.
  - Settled `mockup.md` decisions stayed settled.
- Regression: code fixes checked before reporting fell to 0/4. The report proposed GDScript fixes (a Timer, an `after_each` move, a test, a camera reset) without compiling any. Step 5 already requires that check, so the rule is there but wasn't followed. Next run: put each proposed GDScript fix in a scratch branch, run `godot.build`, and drop or mark unverified any fix that isn't checked.
- Found while fixing #1: `await wait_seconds()` in GUT resumes inside a physics frame, where `Input.is_action_just_pressed` is false for a press made there. The `test_main` corner test waits one process frame before pressing. Candidate for the `write-test` skill.
