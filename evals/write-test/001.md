## Findings

### a) The test can't tell previous from next

The fixture has two structures, and with two, `wrap(i - 1, 0, 2) == wrap(i + 1, 0, 2)` for every `i`.
The agent's test (from 0, expect 1, a new preview showing `grass.glb`) stays green when
`structure_previous` behaves like `structure_next` (`a1`). The agent's own red mutation
(`index - 1` → `index`) didn't probe this. No start index fixes it: it needs three or more
structures.

- **Human edit** (`2700d15`, from the user's review): the test adds a third structure of its own
  (`pavement.tres`), so the shared fixture and the other tests stay as they are, and expects index 2
  and `pavement.glb`. Grader: red on `a1` (index 1, `grass.glb`), red on `a2`, green on the code; suite
  46/46, 0 orphans.
- **Proposed rule** for the skill: a test of one of two symmetric actions (`next`/`previous`,
  `rotate` left/right) uses inputs where the two give different results, and is seen red with the
  other action in its place.

### a) A latent bug in the builder fixture (found by the agent, confirmed)

`before_each` called `builder.set_process(false)` before the builder entered the tree. READY turns
`_process` back on for a script that defines it, so every test builder ran `_process` with no
camera. The new test made it visible (`Cannot call method 'project_ray_origin' on a null value`,
only in the full suite). The grader re-checked it: with the call moved back, the suite fails 43/44 on
exactly that error. The agent moved the call after `viewport.add_child(builder)`. Committed on its
own (`10b4b97`).

- **Proposed rule** (the agent suggested it): `SKILL.md`'s "Call `builder.set_process(false)`" should
  say *after* the builder enters the tree.

### b) The new test alone passes when nothing charges

`test_rebuilding_same_structure_on_its_tile_does_not_charge` reads the cash after the first build and
checks it doesn't move. If no build ever charged (`b2`), it would still pass. The suite catches `b2`
through the existing `test_build_charges_price_and_places_tile`, so nothing is lost here. On its own,
though, the test doesn't prove the first build paid. Proposed ✅, since the claimed behavior (`b1`) is
caught.

### c) Red only through a broken expectation

The code already behaved as asked, so the agent saw red by expecting `1` instead of `-1`. The skill
allows that ("a temporarily broken expectation"), but it shows the assertion can fail, not that the
test catches a break in the code. Both grading mutations were caught anyway: the test puts structure
`1` on the tile, so neither "clear nothing" (`c1`) nor "write 1" (`c2`) leaves `-1`. That depended on
which structure the agent picked.

- **Proposed rule**: for behavior the code already has, see the test red by breaking the code (a
  hand-made mutant reverted after), not only the expectation. a and b did; c didn't.

### d) Run 1 read the answer from git

The setup was left as uncommitted changes on top of `main`. The agent ran `git diff` and found that
HEAD (`d3fd2d6`) already had the guard and both tests. It restored them, renamed the helper and
reported it. Its result is HEAD's tests, so grading it would only re-grade them. Discarded.

The re-run started from an orphan branch holding the setup as its only commit: no diff, no history.
The answer was still reachable through `git log --all` and two docs that describe the guard
(`.claude/skills/generate-ui/SKILL.md`, `evals/review-pr/004-pr4.md`). Nothing in the agent's report
suggests it used them. It found on its own that GUT's panel is the hovered Control in the root
viewport (a CanvasLayer didn't help), and moved the builder into a `SubViewport`, as `d3fd2d6` did.

- **Rule for the next eval** (for `tasks.md`, not the skill): a task whose setup removes committed
  code runs from a history-free branch.

### d) Two remarks in the re-run's report

- `demolish` is the Delete key, so the guard also blocks Delete while the pointer is over UI. That is
  the known answer's behavior too; the agent raised it as a product choice.
- "4 ObjectDB instances were leaked" at exit in its failing runs: not reproduced. The grader ran GUT
  directly on its final tests, failing (setup) and passing (fixed): no leak or "still in use" lines in
  either. Probably from an intermediate attempt (the CanvasLayer one).
