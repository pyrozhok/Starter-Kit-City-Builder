## Findings

### f) A press released in `after_each` still reads as just pressed in the next test

The agent's second test, `test_rotate_is_ignored_without_press`, starts with
`await get_tree().process_frame`. The grader checked its reason: with the `await` removed, the test
fails on the correct code (the selector turned 90°). `Input.action_release()` doesn't clear
`is_action_just_pressed()` until the next frame, so an action the previous test pressed still fires.

`main` has a test of the same kind, `test_preview_is_not_rebuilt_without_toggle`. It passes only
because no test right before it presses `structure_next` without awaiting a frame. Checked: with a
probe test that only presses `structure_next` placed before it, it fails (the preview is rebuilt, and
GUT counts 2 orphans).

- **Proposed rule** for the skill (Testing `builder.gd`): a test that checks an action does *nothing*
  without a press starts with `await get_tree().process_frame`; a release in `after_each` takes effect
  only on the next frame.
- **Proposed test change**: the same `await` at the start of `test_preview_is_not_rebuilt_without_toggle`.

### f) Orientation on build untested

The known answer includes that a build after `rotate` stores the selector's orientation
(`get_orthogonal_index_from_basis`, `builder.gd:95`). Neither test checks it, and no grading mutation
covered it. A gap in the task's mutations as much as in the test.

### e) Red on another variant than the nearest one

The agent saw red on "charge the old price" (`e3`), not on "charge only on an empty tile" (`e1`). Its
inputs catch `e1` anyway (grader). The rule asks for red on the nearest wrong variant; here a second
mutant would have been the evidence.
